# Disable Text Selection on Titles, Labels, and Badges

### Date Edited / Applied `(required)`

```
- Edited and applied: 2026-10-12
```

### Type of Change `(required)`

```
- UI / CSS (presentation only)
```

### Requested By / Source `(optional)`

```
- Requested by project owner. Observed across the system: pressing/dragging on
  "worded" display elements (page title in the top bar, headings, status badges)
  highlighted/selected the text, which felt document-like rather than app-like.
```

### Problem `(required)`

- Display-only text such as the page title (`<h2>` in the top bar), section
  labels, card headers, form labels, and status badges could be selected /
  highlighted by the user, and the I-beam (text) cursor appeared over them.
- Location: system-wide, e.g. the page title in the top bar on every page
  (`resources/views/layouts/app.blade.php:79`), and headings/labels/badges
  throughout.

### Root Cause `(required)`

- No `user-select` / `cursor` rules existed for these elements. The only
  related rule was in the print stylesheet (`.app.css` `button, a { cursor:
  default; }`), which does not affect screen use. Browsers therefore treat all
  heading/label text as selectable document text.

### Files Changed `(required)`

- `resources/css/app.css`
- `public/build/assets/app-*.css` (compiled output — regenerated by build)
- `public/build/manifest.json` (regenerated by build)
- `documents/DisableTextSelection.md`

### What Parts Changed `(required)`

#### `resources/css/app.css`

**Before:** no rule existed for these elements (only the `body` block was
present after the box-sizing reset).

**After:**

```css
/* Non-interactive display text: prevent highlight/selection (titles, labels, badges) */
h1, h2, h3, h4, h5, h6,
.topbar,
.section-label,
.card-header,
.detail-hero,
.form-label,
.badge,
.status-badge,
.cit-pill {
    -webkit-user-select: none;
    -moz-user-select: none;
    user-select: none;
    -webkit-touch-callout: none;
    cursor: default;
}
```

### Behavior of the New Changes `(required)`

| Scenario | Before | After |
|---|---|---|
| Drag/click over the page title, headings, badges, labels | Text highlighted (selected) | No highlight; no text selection |
| Hover over a heading/label/badge | I-beam text cursor | Default arrow cursor |
| Long-press a heading on mobile (iOS) | Callout / selection | No callout / selection |
| Select a citation number, plate, amount, notes | Selectable/copyable | Selectable/copyable (unchanged) |
| Select text inside form inputs / textareas | Selectable/editable | Selectable/editable (unchanged) |
| Browser F7 "Caret Browsing" | User/browser controlled | User/browser controlled (unchanged — a site cannot toggle this) |

### Impact & Risk `(required)`

```
- Affects: all pages that load resources/css/app.css via @vite — staff app
  (layouts/app), guest layout, welcome, citizen pages, ticket/print pages.
- Risk: low (purely presentational). The intended side effect is that heading,
  label, and badge text can no longer be selected/copied. Real data (citation
  numbers, plates, amounts, notes) and all form fields were deliberately left
  selectable, so copying of operational data still works.
- Accessibility: screen readers are unaffected. Keyboard focus and clicking
  labels to focus their input still work.
```

### Database / Migration Impact `(optional)`

```
- None.
```

### Untouched `(optional)`

- No PHP, controller, model, route, policy, or Blade view was changed.
- Inputs, textareas, selects, `.selectable`/`<code>` regions, and data cells
  remain selectable.
- Print CSS was already separate and is unaffected.

### Known Issues / Follow-ups `(optional)`

- This does NOT and cannot disable the browser's F7 "Caret Browsing" mode — that
  is a user/browser (and sometimes OS) accessibility setting with no web API.
- Browsers may cache the old CSS bundle; a hard reload (Ctrl+F5) may be needed.
  The Vite asset hash changed (`app-<hash>.css`), so a normal reload should pick
  it up.
- If a heading ever needs to be copyable in future, remove its selector from
  this block (or add a `.selectable` override).
