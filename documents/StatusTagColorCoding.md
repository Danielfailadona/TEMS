## Status Tags Aligned to Color-Coding Rule

### Date Edited / Applied `(required)`

- Edited and applied: 2026-09-21

### Type of Change `(required)`

- Refactor / styling (status badge colors)

### Requested By / Source `(optional)`

- Requested by user with reference to a color-coding rule:
  - `#10B981` Green: Paid, Money, Resolved
  - `#1473F9` Blue: Security, Links, Interactive
  - `#EF4444` Red: Destructive, Anomalous
  - `#f59e0b` Amber: Warning, Action Required Soon
  - `#69757F` Gray: Neutral, Informational, Inert
- Observed across admin citations list, impounding/clamping pages, appeals.

### Problem `(required)`

- Status badges used Bootstrap default palette colors instead of the rule:
  `bg-primary` (`#0d6efd`), `bg-success` (`#198754`), `bg-warning` (`#ffc107`),
  `bg-danger` (`#dc3545`), `bg-secondary` (`#6c757d`).
- No status maps to amber/yellow; "Overdue" was yellow (`#ffc107`).
- `citizen/citation-detail.blade.php` prefixed the class with `bg-`, producing
  invalid `bg-bg-*` class names (badges/header silently unstyled).
- Locations: list/tag badges across citations, clamping, impounding, appeals,
  owner/citizen pages.

### Root Cause `(required)`

- `badgeClass()` in the three status enums returned Bootstrap utility classes,
  which hard-code Bootstrap's own hex values. There was no shared semantic
  palette, so every module drifted toward a different meaning (e.g. clamping
  "Paid" was blue, citations "Paid" was green).
- Two view files constructed the badge/header class prefixes manually instead of
  relying on `badgeClass()` alone.

### Impact & Risk `(required)`

- Affects: status badges on citations index/show/ticket/handoff, impounding
  index/show, clamping index/show, appeals index/show, owner dashboard,
  owner clamping/citations, citizen pages, frontdesk, payments create.
- The `tag-*` classes are new; browsers may serve stale compiled CSS until a hard
  reload (Ctrl+F5). A cached `app.css` without the `.tag-*` rules will render
  badges without background.
- Risk: any place that still pnames the old `bg-*` return values would break. All
  usages of `badgeClass()` were checked; the only two hardcoded/prefix sites were
  the ones fixed. `citations/print.blade.php` uses `.status` (its own border
  style), not the badge, and was intentionally untouched.

### Database / Migration Impact `(optional)`

- None

### Untouched `(optional)`

- Status labels/enum values (Issued/Paid/Overdue/Clamped/Released, etc.)
- Controllers, models, routes, authorization logic
- All other `badgeClass()` call sites (they interpolate the returned class directly)
- `citations/print.blade.php` `.status` styling

### Known Issues / Follow-ups `(optional)`

- Vite build required after CSS edits: `npm run build` (npm shim is blocked by
  PowerShell execution policy; use `npm.cmd run build`).
- Amber (`#f59e0b`) intentionally uses dark text `#1f2937` for contrast.
- Overdue, Clamped, Awaiting Payment, Rejected now share red/amber semantics per
  the rule; operators may want additional distinct icons if needed.

### Testing / Verification `(required)`

- `php -l` clean on all edited PHP/Blade files.
- `npm.cmd run build` — Vite compiled `app.css` with `.tag-*` classes
  (confirmed `.tag-green/.tag-blue/.tag-red/.tag-amber/.tag-gray` present in
  `public/build/assets/app-*.css`).
- `php artisan view:cache` / `view:clear`.
- Manual QA (hard refresh): citation "Overdue" amber, "Clamped" red, "Paid" green,
  "Issued" blue, "Released" green on `/citations`; clamping badges on
  `/impounding`; appeal badges on `/appeals`; citizen citation detail header and
  appeal badge now colored.

## Clamping "Awaiting Payment" Re-classed Red to Amber

### Date Edited / Applied `(required)`

- Edited and applied: 2026-09-21

### Type of Change `(required)`

- Bug fix (status tag color misclassification per the color-coding rule)

### Requested By / Source `(optional)`

- Requested by user after auditing `/impounding` against the rule:
  - `#10B981` Green: Paid, Money, Resolved
  - `#1473F9` Blue: Security, Links, Interactive
  - `#EF4444` Red: Destructive, Anomalous
  - `#f59e0b` Amber: Warning, Action Required Soon
  - `#69757F` Gray: Neutral, Informational, Inert

### Problem `(required)`

- `ClampingStatus::AwaitingPayment` rendered `tag-red` (`#EF4444`). Red is reserved
  for destructive/anomalous states; awaiting payment is a warning that calls for
  action, which the rule maps to amber (`#f59e0b`).

### Root Cause `(required)`

- The `badgeClass()` map in `app/Enums/ClampingStatus.php` assigned `AwaitingPayment
  => 'tag-red'` when the rule was first applied (see first entry above).

### Files Changed `(required)`

- `app/Enums/ClampingStatus.php` (one line in `badgeClass()`)
- `documents/StatusTagColorCoding.md` (this log)

### What Parts Changed `(required)`

`ClampingStatus::badgeClass()`:

**Before:**

```php
self::AwaitingPayment => 'tag-red',
```

**After:**

```php
self::AwaitingPayment => 'tag-amber',
```

Current full map:

```php
self::AwaitingPayment => 'tag-amber',  //  Warning, Action Required Soon
self::Paid => 'tag-green',             //  Paid, Money, Resolved
self::WaitingRelease => 'tag-amber',   //  Warning, Action Required Soon
self::Released => 'tag-green',         //  Paid, Money, Resolved
```

### Behavior of the New Changes `(required)`

| Scenario | Before | After |
|---|---|---|
| Impounding list status badge (index line 39) | Awaiting Payment red `#EF4444` | Awaiting Payment amber `#f59e0b` (dark text) |
| Impounding show badge (line 77) | red (via same enum) | amber (via same enum) |

No CSS change: `tag-amber` already exists in `app.css` (compiled), so no Vite
rebuild required.

### Impact & Risk `(required)`

- Affects: all badge renderings of `ClampingStatus::AwaitingPayment` (impounding
  index + show). Low risk - enum value/string unchanged (`awaiting_payment`);
  only the CSS class name changed, and it is already defined.

### Database / Migration Impact `(optional)`

- None

### Untouched `(optional)`

- `CitationStatus::Clamped` remains `tag-red` (judgment call: clamped = anomalous,
  unresolved) - not changed unless the user confirms.
- Filter toggle buttons on `/impounding` use their own Bootstrap outline colors
  (`btn-outline-danger` etc.) and are not status tags.

### Known Issues / Follow-ups `(optional)`

- `CitationStatus::Clamped` still red; revisit if the user wants it amber.

### Testing / Verification `(required)`

- `php -l app/Enums/ClampingStatus.php` - clean.
- `php artisan view:cache` / `view:clear`.
- Manual QA (hard refresh): `/impounding` "Awaiting Payment" badge is amber,
  "Paid" and "Released" green, "Waiting to Release" amber.
